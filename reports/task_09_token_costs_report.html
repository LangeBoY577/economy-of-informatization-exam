1. Экономическая постановка задачи¶

Компания «ГосТех» запускает AI-чат поддержки граждан. Затраты сильно зависят от того, как его построить. У API-провайдера платим за токены, то есть затраты почти полностью переменные. Свой сервер с open-source моделью даёт почти только постоянные затраты (GPU, персонал). Гибрид с кешированием уменьшает переменную часть. Объём запросов растёт, поэтому выбор зависит от того, где проходит точка безубыточности.

Цель: выбрать самую дешёвую схему на 3 года и найти объём, при котором выгоднее свой сервер.

Тема лекции №10: экономика работы моделей, стоимость токенов, open-source против API, TCO вычислительных ресурсов.

monthly_requests = {1: 50_000, 2: 200_000, 3: 500_000}   # запросов в месяц по годам
tok_in, tok_out = 300, 150                               # токенов на запрос
r = 0.12; H = 3
# 1.2. Вариант 1 — API (GPT-4 Turbo)
p_in, p_out, price_growth, api_integration = 0.01, 0.03, 0.05, 5_000      # $ за 1K токенов; $ разово
# 1.3. Вариант 2 — self-host (Llama 3 + fine-tune)
sh_capex = {"Оборудование 4×A100": 40_000, "Fine-tuning": 5_000, "Интеграция": 8_000}
sh_opex = {"Эксплуатация": 3_000, "DevOps (частично)": 10_000, "Электричество и охлаждение": 2_000}
# 1.4. Вариант 3 — гибрид (API + кеш)
cache_share, cache_cost = 0.40, 2_000
cost_per_request = tok_in / 1000 * p_in + tok_out / 1000 * p_out
print(f"Стоимость запроса через API в 1-й год: {tok_in}/1000·{p_in} + {tok_out}/1000·{p_out} = ${cost_per_request:.4f}")

Стоимость запроса через API в 1-й год: 300/1000·0.01 + 150/1000·0.03 = $0.0075

Допущения:

  • Объём в условии дан в месяц, поэтому за год умножаем на 12 (0,6 / 2,4 / 6 млн запросов в год). Для сравнения отдельно показан расчёт, если считать эти объёмы годовыми.
  • Разовые затраты (интеграция, оборудование, дообучение) в момент t = 0, текущие в конце каждого года.
  • Гибриду тоже нужна интеграция с API (5 000 $), как варианту 1. Цены API растут на 5 % в год со 2-го года.
  • 4×A100 с большим запасом хватает на 500 тыс. запросов в месяц (в среднем около 0,2 запроса в секунду).

3. Математическая модель¶

$$c_t = \Big(\tfrac{300}{1000}\cdot0{,}01+\tfrac{150}{1000}\cdot0{,}03\Big)(1{,}05)^{t-1},\qquad C^{API}_t = 12\,Q_t\,c_t,\qquad C^{гибр}_t = 0{,}6\cdot12\,Q_t\,c_t + 2000$$ $$C^{self}_t = OPEX = 15\,000\ \$,\qquad PV = C_0+\sum_{t=1}^{3}\frac{C_t}{1{,}12^t}$$ Точка безубыточности: такой объём $Q^*$ (во сколько раз больше плана), при котором $PV^{API}(Q^*) = PV^{self}$.

def costs(volume_mult=1.0, price_mult=1.0, annual_volumes=False):
    """Таблица затрат по годам ($) для трёх вариантов."""
    rows = []
    for t in range(H + 1):
        q = 0 if t == 0 else monthly_requests[t] * volume_mult * (1 if annual_volumes else 12)
        c = cost_per_request * price_mult * (1 + price_growth) ** (t - 1) if t else 0
        rows.append({"Год": t, "Запросов в год": q, "Цена запроса, $": c,
                     "API": api_integration if t == 0 else q * c,
                     "Self-host": sum(sh_capex.values()) if t == 0 else sum(sh_opex.values()),
                     "Гибрид": api_integration if t == 0 else q * (1 - cache_share) * c + cache_cost})
    return pd.DataFrame(rows).set_index("Год")

6. Интерпретация результатов¶

  • Один запрос через API стоит **$0,0075** (около 0,7 руб.), но при 6 млн запросов в 3-й год счёт доходит примерно до $50 тыс. в год.
  • Самая низкая TCO за 3 года у гибрида. Кеш на 40 % запросов почти вдвое снижает переменные затраты, а стоит всего $2 тыс. в год. PV: гибрид около $42 тыс., API около $59 тыс., свой сервер около $89 тыс. Свой сервер самый дорогой на 3 годах из-за $53 тыс. разовых вложений.
  • Когда окупается свой сервер. По текущим расходам он дешевле API уже с 167 тыс. запросов в месяц, это будет во 2-м году. Но разовые $53 тыс. окупаются только при большей нагрузке: по TCO за 3 года он сравнивается с API при нагрузке в 1,5 раза выше плана (около 770 тыс. запросов в месяц в 3-й год), а с гибридом в 2,4 раза выше (около 1,2 млн).
  • Чувствительность. Гибрид остаётся лучшим при объёме ±30 %, ценах API ±20 % и доле кеша от 20 до 60 %. При +30 % объёма и дорогом API разрыв со своим сервером сокращается. Если же считать объёмы годовыми (в 12 раз меньше), API намного дешевле своего сервера, лучший вариант чистый API. То есть решение сильно зависит от реальной нагрузки.

7. Выводы и рекомендации¶

  1. Выбор: гибрид (API + кеширование). Самая низкая TCO, быстрый запуск, не нужно покупать GPU, качество сильной модели.
  2. Как развивать: запуск на API, затем кеш типовых вопросов (вопросы граждан часто повторяются, реальная доля кеша может быть выше 40 %), а при стабильной нагрузке больше 1 млн запросов в месяц переход на свой сервер с дообученной моделью.
  3. Что отслеживать: стоимость запроса, долю попаданий в кеш, качество ответов (CSAT, доля передачи оператору), объём за месяц и прогноз.
